## What is implemented

**Source investigation and acquisition.** The existing photo-request ledger can follow exact story-retained artist, publisher, gallery, institution and project links without a new host rule for each subject. Captured page links need local project/maker evidence; generic searches/categories, private/staging and social sign-in routes are excluded. New requests bind the connection policy and exact source candidates. Old receipts keep their original permission scope.

Public HTTPS reads check every DNS answer and pin the TLS socket to a checked public address on every hop. Redirects stay on the source host or an exact already-bound destination; image redirects require exact captured variants. No cookies, credentials or referer are forwarded, and no retries occur. File reads are bounded, MIME checked, privately decoded and hash-deduplicated. An unfamiliar CDN is eligible only when its exact image is present in intact network-captured HTML. Saved-page imports cannot authorize downloads. A proxy that cannot preserve endpoint pinning stops clearly; the code does not bypass cloud egress restrictions.

The same source progression retains captured pages, finishes remaining 40-reference windows, resumes eligible pending files and moves to remaining project leads. Standalone picture/lazy markup, unquoted attributes and ImageObject metadata are extracted, preserving established reference identities. Parser v4 derives new views without rewriting historical captures.

**Founder-confirmed photo assessment.** Studio can choose one to six privately saved, receipt-bound JPEGs, prepare an unpaid exact review, disclose input sharing/limits/estimated cost, and confirm only under a separately approved private photo policy. The feature is disabled by default. A missing photo extension does not alter caption/story approval. A fresh review can be prepared after policy changes; consumed/uncertain requests are never reused.

The reusable native proposal uses the existing worker/queue/claim/failure/delivery mechanism. Six fixed structural native routes support input counts 1–6; only the selected route executes one GPT-5.4 assessment. Compact output stays at 1,200 tokens, low reasoning, no tools/search/research/drafting, `store:false`, no configured node retries. Real complete results and measured failures are bound to exact execution/version/graph/manifest and retained in history. Shared one-operation-in-flight, durable idempotency, usage and Disable future AI starts cover all operations. An optional one-operation policy limit supports the first supervised acceptance and remains consumed after failure/restart. Ordinary caption/story counts are unaffected.

**One coherent editorial package.** Current source/private-file/visual evidence produces one cover and sequence proposal, reasons, alternatives, exclusions, source/credit/rights gaps, and image-grounded opening directions beside the writing and final review. A weak, uncertain or omitted frame cannot return through metadata fallbacks to pad the carousel. Metadata suggestions remain explicitly distinct from visual judgments. Only explicit Apply changes the private edit; caption, source evidence and previous order/history survive.

Caption improvement can carry bounded observations of the **currently selected** images through the existing `caption_improvement_v1` research context. The full request/evidence hashes bind those observations; they are labelled advisory visual evidence, not verified facts or instructions. Proposed images are separate. No factual research is trimmed and the native 30k input guard remains. Missing/stale/simulated or over-budget observations are excluded and explained in request review. Source, working-version or file changes invalidate the old visual context rather than silently reusing it. Caption drafting still needs its existing founder confirmation; no new writing engine or native caption change was introduced.

The accepted workstation remains. Unavailable vision tools collapse to one line; the existing prepared-source action sits under “What was checked?” instead of competing with Find more photos. Exact-content approval handoff and guarded native publishing authority remain unchanged. No Buffer writer was added or enabled.
