# One coordinated Studio → Buffer release

Prepared locally on November 17–18, 2026. **Not deployed, no live credential changes, no native installation and no Buffer writes.** The accepted interface remains. Recurring caption/story AI and all publishing history are untouched.

## What is implemented

The existing Preview → Prepare for approval → Approve post → Send to Buffer → Check delivery flow now has a real server-side native connection behind a disabled private policy. Preparation checks the native story title/direction/stage and package identity against the saved source before writing, then sends an immutable saved caption/order to the existing production worker, retains the prior package in its existing revision log and registers source-backed new photos as **unreviewed**. It reuses the actual native slide planner, original-byte verification, renderer and final approval; no publishing engine or provider write client was added to Studio.

The preview/approval gate follows the actual native render contract: rendering may leave `final_caption` empty until human factual signoff. It checks the unchanged native working caption and version-bound files, then requires the existing fact/credit confirmation before final approval. Native finished JPEGs are downloaded privately, fully decoded and hash-checked for the preview. The existing preparer can preserve those exact clean JPEG bytes. Source acquisition hashes, per-image permissions or documented four-factor editorial exceptions, native facts/credits signoff and final human approval remain required. Local approval preparation cannot grant rights. Development-only stories still need acceptance into the existing canonical production process; a preview is not a production original.

Both existing Buffer writers reserve the **same canonical package row** before any provider create. The three additive fields are `buffer_claim_state`, `buffer_claim_owner`, `buffer_claim_digest`. Reads cover both handoff histories across every version. Unknown outcomes, prior IDs (including abandoned rows with IDs), and historical missing Buffer items block recreation. Claims bind caption, ordered files, version and rights evidence. Every conditional update requires its actual returned row ID plus a fresh independent owner/state/content read. An uncertain claim is never automatically released.

The original guarded writer had counted earlier rendered files against a new batch. It now validates the exact current package/version/render batch while retaining older files. Media staging compares actual downloaded public JPEG bytes with the approved private hash, replacing HEAD-only evidence. Provider creation is followed by a **separate `get_post`**: exact destination, caption, slide URL order, `draft`, explicit `dueAt:null` and `sentAt:null` are required. A 202 native receipt means *in progress*, never delivered. Lost replies and restarts reconcile the existing request/execution and saved candidate ID without resubmission.

No current photograph has been relabeled rights-cleared by this work. Small source previews remain subject to existing original-resolution gates.
