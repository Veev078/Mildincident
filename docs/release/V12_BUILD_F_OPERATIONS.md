## Private native connection: less repeated operator configuration

Hosted Studio now reads the existing secure connection contract again before inspection/start and during normal delivery. It uses `STUDIO_RESEARCH_CONNECTION_FILE` when explicitly configured; otherwise the fixed private path is **`STUDIO_DATA_DIR/research-connection.json`**. Missing files mean read-only delivery. Malformed files fail closed to read-only with a review-needed explanation; expired valid files also disable execution while preserving delivered work.

The file remains a0600 nonsymlink regular file within the private persistent root and outside the backed-up editorial workspace, bounded to16KiB. This keeps dispatch credentials out of editorial backup downloads. Its existing table/worker IDs, authentication, exact active version, expiring single-run permit and fingerprint checks remain mandatory. Nothing in the browser can write this file, install a workflow, select credentials or arm a grant. All normal delivery remains GET-only.

After separate approval, an operator can atomically replace the reviewed file at the same path without a Render restart or repeated environment edits. The native worker still has to be at the separately approved exact active version. Removing/replacing a grant does not erase its durable consumed claim. Invalid configuration cannot fall back to a more permissive connection.

A session containing several individually bounded runs is feasible only with independently approved job/hash/direction/evidence/expiry entries and a correspondingly reviewed native graph. Today's recovery graph deliberately pins **one exact job**, so a bundle cannot be treated as permission for an unlimited or recurring session. Build F keeps one fresh grant at a time and reduces restart/configuration friction; it does not introduce multi-run spending authorization. Native installation remains a separate operator action.
