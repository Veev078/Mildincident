## Smallest next functional milestone

**A founder-confirmed caption improvement from retained evidence, without another manual Codex setup for every request.** Reuse the same worker, source-bound drafting operation, job ledger, request hash, version checks, receipt and result reconciliation. Current caption grants bind a reviewed graph to one exact source/evidence/request/direction; they cannot safely be treated as reusable generic authorization. Standard Generate Stories uses the same existing queue/start path but still needs an active approved worker and private fresh single-run grant.

Proposed pilot policy, requiring founder approval before implementation/activation:

1. One operation in flight; one result per action. Founder confirms the exact story/direction, planned limits and estimated exposure before a new grant. Suggested daily request allowance: three story generations and six drafting-only improvements. Request-count limits are enforceable; estimates are not billing caps.
2. Preserve the existing per-operation budgets (research3500 output tokens/two requested searches; draft1800 output), no automatic retries/resubmission and stop on uncertain completion. Show measured usage separately from estimated charges and unresolved tool records. A suggested $2/day review threshold would be monitored, not a promised hard cap on hidden Cloud activity.
3. Server/operator provisions a new expiring single-use authorization for each confirmed request under the approved policy, scoped to worker version/job and, for caption improvement, exact evidence/source revision/direction. No credentials or grant installation from browser fields. Consumption and daily counters must be durable across refresh/restart, and uncertain outcomes retain their claims.
4. First automate the existing exact caption request/review-package preparation and test the renewal path with injected transports. Any minimal change needed to the existing native worker to accept per-request evidence bindings must be separately reviewed and authorized; do not add another workflow/engine or silently widen the current grant schema. Only after that review authorize a bounded live founder action. Native activation/installation and model spending remain separate approvals.
5. A disable control may prevent future starts; never label it as guaranteed cancellation of accepted provider work. Keep approval/publishing entirely separate.

This is a recommendation, not an installed spending policy or an active execution grant. Prior spent/expired permits stay spent/expired.
